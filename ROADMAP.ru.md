## Другие архитектуры
Сейчас все пакеты собраны под x86_64, а архитектура есть только в имени архива.
- [x] Платформа в индексе (`builds` по `<ОС>-<архитектура>`): клиент берёт только сборку под свою ОС и процессор и ничего не компилирует
- [ ] Пакеты и CI для aarch64 (сам WARP собирается и проходит свои тесты на linux/aarch64 в машине OrbStack на MacBook; раннер и опубликованные пакеты ещё впереди)
- [ ] riscv64 — когда появится реальная плата для тестов
- [ ] Библиотека C в платформе. glibc, musl (Alpine, Void musl) и bionic (Android) это разные ABI, а у Void Linux есть и glibc, и musl: сейчас `linux-x86_64` означает glibc, поэтому машина на musl возьмёт сборку, которая даже не запустится (проверено: динамическая сборка на Void musl отвечает «not found»). Решение: платформа узнаёт libc, определяемую во время работы (по интерпретатору `/bin/sh`), а не при сборке. Сборки: `linux-x86_64` (glibc, как раньше), `linux-x86_64-musl` и `linux-x86_64-static` для полностью статической сборки, которая работает на любом Linux. Клиент берёт сначала свою точную libc, потом статическую; машина на musl никогда не возьмёт glibc-сборку. Полностью статические пакеты (Go, Rust, официальные статические сборки вроде ripgrep, jq, btop) публикуются один раз как `static`. Сам WARP поставляется статическим бинарником (`tools/build-static.sh`: работает и на Gentoo с glibc, и на Void musl). Опрос и переключатели на сайте тоже узнают libc
- [ ] CI-раннеры для других платформ (каждый становится отдельным workflow, чтобы блок CI на сайте его показывал): нативный macOS (на MacBook), linux/aarch64 (машина OrbStack на MacBook уже готова), Termux (пока нет; запускать вручную, когда телефон дома и на зарядке, чтобы не сажать батарею вне дома)

## Версии бок о бок (идея пользователя, 2026-10-01)
Сейчас в хранилище уже лежит несколько версий (`store/<имя>-<hash12>`), но ссылка `prev` одна: откат переключает между двумя.
- [x] Поставить любую версию: `warp install имя@1.2`, `warp versions имя` (установленные и доступные); индекс хранит старые версии (`имя@версия`)
- [x] `warp switch имя <версия>` на любую установленную; откат идёт назад по истории активаций, а не по одной ячейке
- [x] `warp pin имя [версия]` / `unpin`: `warp upgrade` не трогает закреплённый пакет (программа требует версию не выше X или не ниже)
- [x] `warp run имя@1.2 -- аргументы`: запустить конкретную версию, не переключая активную
- [x] `warp gc`: удалять версии, которые не активны, не закреплены и не в недавней истории (диск ограничен)
- [ ] Разные зависимые пакеты используют разные версии одной зависимости одновременно (модель замыканий Nix): пакеты должны находить зависимости по пути в хранилище; после резолвера зависимостей

## macOS (нативно)
Проверено на Apple Silicon без Homebrew: WARP собирается одними Command Line Tools, линкуется только с системными `libcurl` и `libSystem`, знает, что он `macos-aarch64`, проверяет настоящий подписанный индекс и с понятным сообщением отказывает в пакете без сборки под macOS.
- [x] Без OpenSSL (свой SHA-256, встроенный Ed25519), для сборки нужны только Command Line Tools
- [x] Бандл сертификатов ищется по системам (на macOS он в `/etc/ssl/cert.pem`)
- [ ] Префикс пользователя без root (`~/.warp` или `/opt/warp`), `warp shellenv` для профиля оболочки
- [ ] Установщик: одна команда, которая объясняет, что сделает, ждёт Enter, скачивает готовый бинарник `macos-aarch64` и показывает отпечаток закреплённого ключа для сверки с сайтом; позже `.pkg` для управляемых установок
- [ ] Данные системы для опроса на macOS (`sysctl`: версия ОС, процессор, ядра, память)
- [ ] Первые пакеты под `macos-aarch64` (ripgrep, jq, btop из официальных релизов) с записью `builds` в индексе
- [ ] Переносимые тесты (без GNU-only `tar -I`, `timeout`, `stat -c`)
- [ ] Два CI-раннера на MacBook: нативный macOS и linux/aarch64 (машина OrbStack, уже подготовлена)
- [ ] Дальше: заменить Homebrew на этой машине на WARP (репозиторий станет базовым)
